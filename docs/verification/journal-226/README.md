# 手账 2.2.6 流畅度验收

基于 2.2.5 `07d9057`，分支 `codex/journal-performance-2-2-6`。本地提交，不推送。保留中性浅／深色、排序、置顶、提醒规则与现有资料库格式。

## 改动

- 提醒查询批量取得计划、发生状态、排除项和置顶信息，取消逐条查询；计算首个有效安排后停止，全部匹配记录排序后分页。已完成列表直接 SQL 分页。农历无次数限制规则直接定位查询月份；有限次数使用实际发生次数与有界检查点，保留闰月、缺日和结束条件语义。
- 页面查询使用独立只读 SQLite 连接和一致快照；计算前释放长事务。每个查询器只有一个工作线程，相同通道只保留最新请求，离页／关闭时取消，旧序号和旧资料版本的结果不应用。规则解析、展示结果及页面结果均有界缓存。
- 数据修改按提醒、笔记、统计与文件分组使缓存失效，无关笔记保存不清空提醒缓存；越过安排时间、跨日和时间回拨会重新计算。采用连接内临时变更触发器，无新增持久表或迁移。
- 搜索防抖 180 毫秒；同条件刷新保留内容，换条件显示加载空态，150 毫秒后才显示更新提示。错误保留可用内容并提供重试。提示独立放在页面标题下，不再撑高顶部或挤掉列表。
- 列表按记录身份复用条目，分页追加；保留选择和滚动位置。文字布局缓存随内容、宽度、字体、主题、DPI 变化更新；按条目预先准备布局，避免首次选择时集中计算。主线程每批预算 4 毫秒，给单条处理留出余量，验收目标仍为不超过 8 毫秒。
- 总览在后台批量读取显示范围及排除项，分类复用月份结果，日期点击只更新当天详情。统计聚合和查询在后台，明细每次 100 条。
- 笔记保留 500 毫秒自动保存及删除前收尾；保存后差异更新列表，相同正文避免重复加载，仅转换当前编辑模式。图片在后台按显示上限解码，缓存最多 64 项／32 MiB，小图不放大，原附件不变；加载图片不会把正文标记为已修改。长标题从开头显示。
- 提醒编辑器即时更新字段可见性，预览防抖并在后台计算；保存校验仍使用当前输入。农历日期仍为“初八”，不添加“日”。
- 调度仍每秒检查，后台计算候选日期，提交前校验规则、更新时间和游标；按计划分批提交，不通过降低检查频率换取流畅。自动备份、附件引用扫描和导出使用后台 I/O；删除附件前再次检查资料版本及备份指纹，发生变化则取消该轮清理，继续保护备份引用。

## 性能结果

验收机器：Windows x64，Intel Core i7-13620H；源码环境 Python 3.13.7、PySide6 6.8.3。全部数据位于临时／隔离资料库，未读取个人资料。计时与编译、截图任务分开运行。

| 混合提醒数 | 原版查询 | 2.2.6 冷查询 | 2.2.6 首批界面内容 | 热切换最大值 |
|---:|---:|---:|---:|---:|
| 0 | 0.30 ms | 0.29 ms | 35.8 ms | 8.2 ms |
| 100 | 30 秒超时 | 143.2 ms | 313.1 ms | 15.4 ms |
| 1,000 | 30 秒超时 | 144.5 ms | 322.1 ms | 16.1 ms |
| 10,000 | 30 秒超时 | 227.3 ms | 473.0 ms | 14.7 ms |

“30 秒超时”表示在限定时间内没有返回，不能据此推算确切倍数。查询与界面时间分别测量，不把 SQL 时间当作完整界面耗时。首次反馈以切页并完成一轮 Qt 事件处理计时，包含首次绘制；源码使用 offscreen 渲染，不能代表显示器扫描输出延迟。窗口对象创建约 270–291 ms，独立记录；正式程序在初始化手账服务时创建窗口，不在点击提醒页时创建。

查询固定 4 次 SQL；六种共享规则的混合样例共计算 20 个候选，热查询无需再推算候选。数据包含从 2000 年开始的公历日／周／月／年及农历月／年重复，另有同量笔记和三倍健康记录。这是确定的压力样例，不等同于所有规则均互不相同的最坏情况。

四种规模均通过首次反馈 ≤100 ms、热提醒页 ≤200 ms、1,000 条冷加载 ≤1 s、10,000 条 ≤3 s、事件循环 P95 ≤50 ms／最大 ≤150 ms，以及列表批次 ≤8 ms 的检查。10,000 条标准切页测试的事件循环 P95 为 11.9 ms、最大 90.4 ms。

10,000 条资料连续切换五页共 100 次：事件循环 P95 6.7 ms、最大 50.1 ms；列表批次最大 6.6 ms。50 次与 100 次切换后的工作集为 176,246,784 和 176,267,264 字节，增量约 20 KiB；页面缓存 4 项，估算约 84.9 MiB（上限 12 项／96 MiB），没有随切页持续累积。缓存估算值不等于进程实际内存。此前发现的集中布局超预算已修正后复测。

后台并发样例：10,000 条提醒、10,000 篇笔记、30,000 条健康记录、16 MiB 附件，同时运行 100 个到期计划检查、自动备份／引用扫描及 ZIP 导出。全部约 497 ms 完成，事件循环 P95 16.6 ms、最大 40.0 ms，17 条通知保持可用。

原始报告见 `performance/`。复现入口：

```powershell
.venv/Scripts/python.exe tools/benchmark_journal.py --output artifacts/query.json
.venv/Scripts/python.exe tools/benchmark_journal_ui.py --count 10000 --output artifacts/ui.json
.venv/Scripts/python.exe tools/benchmark_journal_ui.py --count 10000 --stress --output artifacts/stress.json
.venv/Scripts/python.exe tools/benchmark_journal_background.py --output artifacts/background.json
```

原版查询脚本使用从 `07d9057` 导出的 `journal_store.py`、`journal_recurrence.py`，通过 `--modules` 指定目录；每个规模独立子进程，默认 30 秒上限。源码 UI 压测等待查询最多 30 秒，后台任务同样有截止时间。

## 功能、截图与发行

回归覆盖日期等价、有限次数与闰月、连续排除、排序和置顶、跨日／回拨、异步旧请求及搜索防抖取消、缓存边界、批量 SQL、调度结果过期、备份引用、只读、格式保存重开、附件与媒体生命周期。351 项完整应用回归、29 项编辑器定向回归、45 项最终定向回归全部通过；`regression-summary.json` 按用例名称去重，共 **353 项**，重复执行的用例不累计。

源码界面矩阵 638 张，浅／深色 × 100%／125%／150%／200%，五页与主要编辑器覆盖正常和 620×420 逻辑窗口；另有 20 张加载、失败、刷新保留内容和重试截图。全部在审阅总览中逐张检查，关键日期、图片、长标题及小窗错误提示另做原尺寸检查，并非每张都原尺寸打开。截图只用于显示状态验收，性能结论取自计时报告。

录音界面截图采用模拟状态，实际播放使用生成的短静音 WAV；未访问麦克风。最终编译版另外验证字体、图标、105 条跨分页全选、只读、置顶、10 点默认、播放结束／释放和 Live2D 独立运行。编译版使用系统显示缩放，完整四档矩阵由源码覆盖。最终编译版 36 张截图，加上源码及加载状态共 **694 张**，见逐文件 SHA256 清单。深色首轮缩窗截图曾捕获列表重排空帧；检查了缩窗后的行位置，并用同一 EXE、新隔离资料库完整复验，重拍结果正常。

最终 EXE 浅色额外 1,000 条混合提醒：提醒内容 198.2 ms，页面加载期间事件循环 P95 12.7 ms／最大 20.3 ms。深色额外 10,000 条：366.3 ms，P95 12.8 ms／最大 91.5 ms，两者性能断言均通过。报告还保留完整验收脚本的延迟（包括直接调用同步存储接口作断言、PNG 编码等，最大约 218 ms）；它与页面加载指标单列，避免把测试工具自身阻塞误算成产品加载延迟。短启动、19 个 Live2D 状态与独立助手无系统操作诊断均通过，见 `package-smoke/`。
